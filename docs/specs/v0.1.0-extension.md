# OpenNetIQ v0.1.0 extension: spectrum, cell scan and G-NetTrack Pro parity

**Mode:** build · **Type:** app · **Spec v3**

**Goal:** Give NICTA field engineers, in one sideloaded OpenNetIQ v0.1.0 APK, the G-NetTrack Pro capabilities they rely on plus a spectrum module, validated in the same Port Moresby field campaign.

**Success looks like:** In the M1 field campaign one engineer drives a route with 2-4 phones (one per operator) running the same test script, and within an hour of returning produces a merged operator comparison (radio, data, QoE, voice/SMS KPIs) and a map of detected cells from OpenNetIQ exports alone, without G-NetTrack.

**For:** NICTA field engineers and analysts (single user per phone, no login, data stays on device until exported).

## Must have
| # | Item | How we test it |
|---|---|---|
| M1 | Cell scan: every cell the modem reports (serving and neighbour) kept per session with RAT, band, ARFCN, PCI, cell ID, best/mean level, sample count, first/last seen | After a 10-minute drive the Cell scan screen lists at least the serving cells seen, grouped by band, and the counts match the samples CSV |
| M2 | Estimated cell layer from own drives, as accurate as the data allows: site position per eNB/gNB from all its cells (timing-advance multilateration when available, else level-weighted centroid), sector azimuth estimate, uncertainty radius and method shown; lines from samples to serving cell on the map; layer merges all sessions | On recorded drives each estimated site shows method and uncertainty radius; tapping a sample draws a line to its serving cell; a synthetic test site is recovered within 150 m when TA data is present |
| M3 | KML export of track (coloured by level), samples and estimated cells | The exported .kml opens in Google Earth with track, sample points and cell markers |
| M4 | Test scripts: user builds an ordered list of steps (speed, latency, file transfer, web, video, app reachability, voice call, SMS, wait) with repeat count or interval; runs during a drive recording and on its own | A script 'speed, wait 60 s, latency' repeated 3 times runs unattended during a recording and stores 6 results linked to samples |
| M5 | Web browsing test: configurable site list; DNS, connect, TLS, first byte, full page load time and success per site (real browser engine) | With 5 sites configured the test stores 5 results with all timings; an unreachable site is stored as failed with a reason |
| M6 | Video streaming test: configurable list of video sources - direct streams (HLS/DASH/MP4) and video on web pages (YouTube, Facebook, game streams); start delay, rebuffer count and time, played time, resolution/bitrate where exposed, failures | With one HLS URL and one web-page video configured, a 30 s test stores start delay and rebuffer events for both; throttling produces at least one rebuffer |
| M7 | App reachability test: configurable list (defaults: Google, Facebook, WhatsApp, YouTube, a PNG bank site); DNS + HTTPS response time and success | Default list returns one row per app with times; airplane mode gives failed rows, not a crash |
| M8 | File transfer test: fixed-size download and upload (default 5 MB) to the test server; time and effective rate | 5 MB download/upload results stored with duration and Mbps |
| M9 | Voice sequence: call a configured number, hold N s, hang up; KPIs call setup success, setup time, drop, duration; dialled number not stored in clear | 10 calls to a test number store 10 results with setup times; ending the call from the far side before N s is recorded as dropped |
| M10 | SMS sequence: send to a configured number (default: own number) and measure send result, delivery report time and receive time | 5 SMS to own number store send, delivery and receive times; message text is not stored |
| M11 | Multi-phone benchmarking: script export/import (file or QR), synchronised start at a chosen UTC time, operator label per phone, and a merge command producing an operator comparison report from several phones' exports | Two phones on different operators run the same imported script from the same start time; onq-validate benchmark merges their exports into one per-operator table |
| M12 | Spectrum placeholder: Spectrum analyser entry on Home opens a 'Coming soon' screen describing the planned tinySA Ultra support | Tapping Spectrum analyser on Home shows the Coming soon screen; no USB permission is requested |
| M14 | FTP throughput test (NICTA QoS Rule 2022 Schedule 2 G8): FTP download and upload of a fixed file (default 100 MB on LTE/5G, 50 MB on 3G) to the campaign FTP server; mean data rate over the whole transfer; serving RSRP/RSCP during the transfer | Against the infra test server, a 100 MB LTE download and an upload store bytes, duration and Mbps; a wrong password or unreachable server stores a failed row with the reason |
| M15 | Campaign tags per session: region, area class (urban / semi-urban / rural) and location name, chosen when a recording or static test starts and exported with every record | A drive started with region Southern, area Urban, location "Waigani" exports these values in samples CSV, tests CSVs and GeoJSON |
| M16 | NICTA compliance report (`onq-validate report --rule nicta-qos-2022`): Appendix A (call failure and drop rate) and Appendix B (FTP DL/UL, ping, web, RSRP/RSCP) per region and area class, pass rates and averages to one decimal place, sample-count checks (100 calls per region, 10 samples and 100 pings per location, 30 locations per region); Excel and CSV | Running it on a set of exports gives Appendix A/B tables whose numbers match a hand calculation on the same CSVs, and lists where the sample counts are short |
| M13 | Consent and privacy extended: new scopes for voice/SMS tests, dialled/SMS numbers hashed, documented in PRIVACY.md (policy 1.1) | Fresh install asks for policy 1.1; voice/SMS steps refuse to run without their consent; exports contain no phone numbers |

## Nice to have (only if time allows)
- Predefined route loading (GPX/KML overlay) on the drive map
- Barometer altitude where the phone has a pressure sensor
- Dual-SIM: measure the non-data SIM's serving cell
- Spectrum compliance check once NICTA assignment data is provided

## Out of scope
- Licensed POLQA/MOS scoring (call KPIs only)
- SMS remote control of the app (security risk)
- Bluetooth or Wi-Fi master/slave control of phones (independent phones, merged later)
- Licence-compliance checks against NICTA assignments (no data yet)
- Operator site-file import (cell layer is estimated from drives)
- Google Play distribution (sideloaded APK only)
- Online upload / backend (Phase 2)
- HackRF / RTL-SDR drivers
- Spectrum analyser driver and USB support (placeholder only until hardware is available)

## Constraints
- Single release: v0.1.0 waits for all phases and their field validation (user decision)
- Sideloaded APK; CALL_PHONE, SEND_SMS, RECEIVE_SMS and USB host allowed
- Kotlin for telephony, calls, SMS, USB; Flutter UI; Drift storage with schema migration v1 -> v2
- Open-source permissive dependencies only (e.g. usb-serial-for-android MIT, media3 Apache-2.0)
- Each phase: own branch, tests, docs, device test by maintainer, PR; coverage >= 80 %
- Methodology document updated and methodology_version bumped for new test types

## Deliverables
- Phases A-F code, tests and docs (feature branches + PRs into develop)
- Updated field-validation protocol and onq-validate benchmark command (Markdown + Python)
- ROADMAP, ADRs (cell estimation, test scripts, QoE method, voice/SMS, spectrum) (Markdown)
- Signed v0.1.0 APK (GitHub Release (after validation))

## Send it back if
- An engineer still needs G-NetTrack Pro for the field campaign
- Any test stores phone numbers, SMS text or call audio

## Open risks
- Android limits on neighbour-cell reporting vary by chipset; cell scan completeness depends on the phone
- Call/SMS behaviour differs by vendor ROM; needs testing on NICTA phones
- tinySA command set may differ by firmware version
